# UE3 MCP 资产操作经验

把用户的描述落实到真实对象和作用链，以最小必要修改达到目标。这里记录判断方法，不记录某张地图的操作脚本、对象编号、颜色配方或坐标。

## 工具参考与适用范围

- 参数、连接、单位、分页、错误码和能力边界以当前工具 Schema、Bridge capabilities 和工具参考为准。本机参考为 `E:/08.Prog_CQ_S1/Doc/Client/AI虚幻3MPC工具使用提示词.md`；其他部署使用对应的工具参考，不假定本机路径、包名或视口编号仍有效。
- 首次接入或接口不熟悉时读相关章节；会话内已确认的内容不重复全文读取。工具名称在这里仅用于说明判断方法，不是可绕过 capability 检查的保证。
- 使用实际 MCP 查询、视口图片和属性反射。不要把桌面窗口识别当作精确对象确认，也不要以 MCP 未支持某能力为由自动改源码、编译或调用不受控写入后端。
- 只问观察时不附带编辑；允许编辑不等于允许保存、覆盖、重建光照或发布。保存和回滚范围按用户要求及当前工具限制处理。

## 从描述定位到作用对象

先理解用户要求改变的是形状、位置、资源外观、场景照明、动画还是声音，以及应保持不变的部分。能够从用户当前选择确认目标时，不必重新遍历全场景。

定位依靠完整路径、所属层、位置、组件与当前视图的交叉证据。名称、语言、对称位置和外观只是候选线索，不证明对象就是目标。

可复用的调查结构是：

`用户指向/画面区域 → 场景 Actor → 实际组件 → 绑定资源 → 有效内部对象或参数`

- 从实际组件引用出发查资源，不按包内名称相似性选择一个看起来相关的模板。
- 一个画面区域可能同时有多个 Actor、粒子发射器和灯光；同一个资源也可能被多个对象共享。改之前确认可见结果由哪些对象共同产生，避免漏改或误改远处实例。
- 精确类过滤不自动覆盖子类。无结果或结果不完整时，调整相关范围/字段并检查实际类，不据此断言对象不存在。
- 查询覆盖的已加载层不等于所有磁盘关卡。核对目标所属层、加载和锁定状态。
- 镜头和地图版本一致时才比较截图；场景身份变化后重新查完整路径。不要把别人的场景编号或成功案例路径搬到当前场景。

## 修改前确定控制点与影响范围

选择直接控制用户目标的最小作用层，不为一个局部问题同时改模板、材质、灯光和全局后处理。确有多个独立贡献源时，分别处理并说明各自作用。

- 变换先确认对象身份和原值；相对要求转换为当前值基础上的绝对目标。区分编辑器视角、CameraActor 和场景模型，单位遵从各接口。
- 修改共享资源自身时，需要独立变体就先复制资源，再沿副本的实际内部对象树编辑，最后绑定到授权实例。复制 Actor 或顶层资源不保证所有依赖自动独立，检查仍共享的引用。
- 引用绑定按实际 PropertyClass、材质槽和组件类型确认兼容性；资产存在不代表能绑定到任意对象，也不代表绑定后已经播放或被游戏调用。
- 曲线和复杂结构按反射确认实际类型及可编辑性。只改变目标语义，保留不相关时间点、切线、插值、透明度等结构；不要套用固定字段名、颜色交换或数值配方。
- 确认影响范围后使用工具要求的 dry_run/apply 协议。批量工具适合已识别、相互关系明确的修改；不拿批量改色代替归因调查。

涉及颜色、光照、粒子或“参数变了但画面没变”，按需读 [视觉归因经验](references/visual-diagnosis.md)。普通移动、选择、查询无需读取该附录。

涉及替换模型、正面朝向、镜像对称或模型上局部特效的定位时，按需读 [模型放置经验](references/model-placement.md)。它解释判断条件，不规定模型、坐标或固定旋转值。

需要从资源库寻找可复用效果，或将动态粒子放到模型局部时，按需读 [资源发现与局部动效](references/asset-discovery-effects.md)。优先使用已建立的 MCP 搜索缓存，不为每次查询重写扫描脚本；缓存命中仍需实际引用和渲染核实。

涉及 AI 换肤、跨多个模型/石块拼接图案、贴图局部拉伸或接缝错位时，按需读 [贴图映射与 UV 重烘焙](references/texture-mapping-rebake.md)。整张图片获批、材质绑定正确及 UV 总体范围吻合，均不证明模型内部映射连续；先区分图片构图、UV、法线和真实几何的影响。

## 区分四种完成证据

| 层次 | 应确认什么 | 不能替代什么 |
|---|---|---|
| 请求 | 工具接受操作或已排队 | 对象已变化、保存已完成 |
| 数据 | 正确对象的值/引用已回读一致 | 运行实例和渲染已刷新 |
| 表现 | 当前视口实际显示所需结果 | 文件已保存、游戏发布结果一致 |
| 持久化 | 所需文件保存完成，必要时重载后仍一致 | 自动 Cook、发布或最终客户端验收 |

对明确的坐标/属性调整，先回读；视觉目标需要查看当前真实图片，不能只拿截图路径或参数宣称看到了结果。动效观察同时确认预览条件，静止画面可能不能证明动画/粒子播放状态。

需要保存时检查资产包、主关卡、流式子关卡的修改归属。地图副本不自动隔离外部资产，也不自动包含共享子关卡；采用接口支持的复制范围，并确认实际文件清单。

重载验证只在持久化风险值得验证时进行，例如新引用、整组关卡另存或跨包修改。先处理用户未保存工作，不为验证自行关闭编辑器、丢弃改动或覆盖文件。

## 失败时缩小问题，不堆叠修改

- 写入超时或连接断开后，结果可能未知。先确认连接、当前地图及目标状态，再决定是否重试；不要盲目重复复制、移动或保存。
- 复制失败先看日志中的实际对象。发布资源的编辑器缩略图等附属对象也可能在复制时触发 BulkData 错误；这不能证明主体模型或粒子不能加载，也不证明所有复制都会失败。不要重复调用已导致崩溃的同一操作，或为绕过复制而擅自保存共享原包。
- 致命渲染错误与缺资源警告分开处理。堆栈涉及第三方叠加层 Hook 时，先排除其注入冲突；窗口仍显示不代表编辑器可继续操作，必须确认 MCP 能响应。崩溃前的内存预览不当作已保存成果。
- 参数正确但效果不符时，检查对象身份、实际绑定、贡献源、预览条件和刷新状态；不要直接归咎于材质、引擎或模型能力。
- 诊断性开关/临时改值会改变用户内容。仅在授权范围内做可恢复对照，记录原值并恢复；无证据的试探修改不叠加进入最终结果。
- 回滚按本次实际操作和当前 Undo 顺序核对，不能用未知数量 Undo 清除用户修改。批量部分失败不等于全部自动回滚。
- 连续检查仍无法缩小原因时，报告已确认事实、剩余假设和所缺证据。需要用户开启预览、选择目标或授权新能力时明确提出，不进行无界搜索或无关稳定性研究。

## 让调查成本与任务相称

围绕目标分批查询必要字段和子对象，用分页和局部范围避免全盘扫描。视角已知时直接跳转；仅在图像能区分假设时重新截图。验证频率按修改风险决定，不要求每个字段都截图、重启、编译或运行全套测试。

输出简述确认的对象/影响范围、实际修改、证据层次、保存位置及未完成项。将事实、假设和限制分开，不把“看起来类似”或“参数已变”写成视觉成功。

## 维护这份经验

共同维护仓库为 `https://github.com/diy72120/ue3-mcp-asset-workflow`。仅在维护本 Skill 时，先读取仓库的 AGENTS.md、CHANGELOG.md 和远端最新内容/差异，再合并修改；不得用本地旧副本覆盖他人更改或强制 push。任务操作时无需为使用经验而同步仓库。

只纳入能改变后续判断的可迁移经验，并说明适用条件和证据限度。接口事实写入工具参考，任务编号、包名、数值、截图和逐步记录保留在该任务的证据中，不加入通用 Skill。

单次观察可以成为待验证假设，不能直接升级为“必须换材质”“某亮度等于关闭”或“某类操作必然崩溃”。发现反例时修正适用范围或删除结论，不不断添加互相冲突的规则。
