# 动画绑定与持久化

适用于将粒子、灯光等效果接入现有动画，以及恢复或迁移演员后出现编辑器与实际游戏表现差异。记录判断条件，不记录关卡名、演员编号、坐标或固定时间配方。

## 恢复外观不等于恢复行为

- 重建演员并绑定原资源，只恢复外观与变换，不自动恢复 Kismet/Matinee 引用。沿实际链路确认 `触发事件 → SeqAct_Interp → InterpData → Group → Track`，以及该组 VariableLink 指向的 SeqVar_Object 和实际 ObjValue。
- 组名和空引用是调查线索，不证明历史上一定绑定过被删演员。区分“恢复已证实的旧关系”与“根据用户需求建立新关系”，不要杜撰删除前逻辑。
- 有开关轨道但没有关键帧，不会自动产生关闭行为。绑定和关键帧分别回读；不要误改相邻组或其他动画的轨道。
- 时间以真实动画、运动/动画控制轨道及触发方式为依据，不硬编码案例时间。核对播放速率、强制起始位置、循环、跳转和正反向事件设置；单次画面不能证明实际触发时机。
- 粒子停止生成不一定立即清除已有粒子。需要瞬时消失时检查停用清除与寿命设置；只改授权的效果，不修改共享原资源来影响所有使用者。

## 跨层绑定先遵从引用规则

- 已加载不等于允许跨包引用。对象引用导入报错时，核对私有对象、关卡归属、PropertyClass 和 CrossLevel 支持，不强行写指针或改变公共标志绕过限制。
- 若控制器只能安全引用本层演员，可评估将独立效果放到控制器所在层。迁移会改变加载、卸载与生命周期，必须适合目标行为；不是所有跨层引用失败都应迁移。
- 迁移保留实际世界变换、组件局部变换、模板和激活条件；新对象确认有效且引用已转接后，才删除旧对象，避免重复效果或失联。保存清单包括新增引用所在关卡和移除对象所在关卡。

## 编辑器正常、游戏缺失时先核对部署

1. 比较用户实际部署路径与编辑器输出的目标文件：存在性、大小和 SHA256。更新时间只能辅助判断；完整一致时停止反复要求重新复制同一批文件。
2. 检查保存包中的目标演员、组件、模板引用、变换和控制链，并与内存状态比较。缓存未必反映刚保存的修改；需要落盘证据时只读解析相关包，不全量重建索引。
3. UE3 可按 Archetype/模板保存差量，未显式出现某属性不等于属性丢失。解释差量前要检查默认值、模板及依赖；编辑器内存值也不能证明独立加载后的有效值。
4. 使用源演员作为 SpawnActor 模板的复制，与从类默认对象新建并显式配置不是同一持久化路径。跨层复制后删除源演员若出现异常，应检查模板依赖与保存结果，不能仅凭复制后的截图断言已独立。
5. 独立效果允许重建且当前工具缺乏可靠迁移时，可从标准类新建、显式设置必要变换和模板、重新接线，并移除故障实例。先确认相关授权，不覆盖其他用户调整，不重复生成副本堆叠“修复”。

## 验证与结论边界

- 普通查询不需要重载；模板复制后删源、跨包迁移或部署差异等持久化高风险操作，值得在授权保存后核对包或重载一次。不要为每个小字段重复启动、编译或完整测试。
- 本经验来源中：部署文件哈希一致，故障演员/组件的显式序列化字段少于预期；独立新建并显式配置后，编辑器截图和用户游戏反馈确认显示恢复。复制接口造成差量/模板依赖异常的具体底层原因仍待核实，不推广成所有复制都不可靠。
- “静态效果重新可见”“关键帧/绑定已回读”“实际动画触发时效果消失”是不同验收项。用户仅确认显示恢复时，不替其宣布动画生命周期已完整验证。
- 工具调用成功、内存值正确、文件存在、游戏确认分别记录。最终只列实际需要更新的关卡/资产包；资产修复不自动要求更换客户端 EXE。
