# 地图制作与发布经验

用于新增或迁移地图，以及“编辑器正常，游戏进图失败”的排查。具体工具参数读取当前 Schema；地图名、编号、文件清单和转储证据留在项目记录，不复制历史任务脚本。

## 1. 先拆清发布链

`目标版本与独立源副本 -> 依赖/类兼容 -> 碰撞及导航 -> 场景数据 -> 地图索引 -> 保存 -> Cook -> 部署 -> 游戏验收`

- UDK 保存世界和流式关系；模型可见不等于该处可通行。主地图不是整组地图的替代品。
- 游戏定制的高度格、导航、NPC/场景数据和服务端 Terrain 各有职责，不能通过改扩展名相互替代。找到实际生产者、格式版本和消费者。
- 地图索引解决 ID、关卡名与配置名映射；不会生成地形，也不会自动注册服务端。首轮可以只验收空图进入，不等于 NPC、传送、小地图全部可用。
- 用户只授权客户端时，说明服务端所需一致性，不擅自修改另一套服务端。原生地图导出、表驱动登记、Cook 是已有流程；MCP 应调用它们，而不是先发明一套二进制格式。

## 2. 迁移按对象引用判断，清理按语义授权

- 明确活动版本，保留旧源地图；独立复制主图、需要独立修改的流式子图和必要依赖。子图包名和主图引用一起核对，地图副本不自动隔离外部资源。
- 包文件存在不证明内部对象存在或类兼容。用缓存缩小候选，再回读真实组件/对象路径；失效缓存不是删除资产的依据。
- 所有网格引用为空的视觉演员、旧版区域标记和缺模板 NPC 要分别判断。无模型的逻辑节点可能有效；“导出器不支持”也不等于没有玩法意义。
- 若用户同意空图试验，可只在测试副本移除确认无效或暂不迁移的对象，记录丢失的语义。不要屏蔽导出器类型检查、忽略坏引用来伪造成功。
- 分组容器和组成员是不同对象。诊断游戏包的编辑器类引用时，精准操作容器并验证成员变换/组件/归属不变；不要以 UI 选组 Delete 代替。正常 Cook 本应处理编辑器对象，手删所有分组不是普遍制作规则。
- 自动保存也会触发序列化。崩溃发生在“尚未点保存”时，先看日志和堆栈，别直接推断是加载或渲染问题。

## 3. 原生类、脚本与资源版本分开验证

旧编辑器配新版资源时，兼容至少包括包格式、序列化属性、原生 C++ 类布局、匹配 `.u` 和运行客户端；某张图能预览不证明后续保存/导出/Cook 都兼容。

- 保存遍历属性或引用崩溃时，核对实际字段偏移与原生类布局。旧脚本反射偏移错误可能读到无效指针，不应先归咎于 VS 版本或地图路径。
- 必要时用匹配的 `.uc` 和原生 make 生成独立编辑器脚本，配套原生头文件/EXE。原生字段变化不能只换一份 `.u` 或一个 EXE。
- 新版发布 `.u` 与编辑器 `.u` 不混放在 Cooker 搜索中；匹配编辑器的脚本不因此成为新版玩家客户端的发布文件。
- 未知新版字段/枚举可能被旧编辑器另存丢失。对涉及的类做原包与副本的属性差异核对，保留未涉及内容；一次差异验证不是未来所有资源的兼容承诺。
- 确定根因后移除临时诊断/过滤，不能把跳过引用或关闭碰撞作为最终修复。需要新增接口/编译时单独申请当前开发范围。

## 4. 导航验收要看语义，不只看结构

- 区分保留碰撞的构建入口和重设图层/选中模型碰撞、删除导航范围的入口。按菜单真实行为选，不凭“AI 路径”名字推断。
- 原生构建前核对流式层已加载、未锁定，导航覆盖、地面/阻挡和输出路径正确。某项目单图导出要求单 Pylon，不代表普通 UE3 只能放一个。
- MCP 返回 queued 只说明已排队；查完成状态、错误和新文件。任务可能改变关卡内导航数据，导出成功后仍需保存相关关卡。
- 规范输出末尾分隔符；核对主导航与障碍导航是否写到同名文件。后一份覆盖前一份可能留下完全合法、却不可通行的数据。
- 检查版本、长度、索引、闭合拓扑之后，再看 XY 面积、可走格标志、范围、顶点修正坐标及高度是否合理。全零坐标、全零面积、全部 out-of-poly 都是语义红旗。
- 固定格式的多边形边数限制优先使用引擎原生拆分；不要扩结构、截边、强制所有格通行。顶点初始化、合并与边界读取问题按实际证据修复，不凭文件存在通过。
- 可选 Terrain 是目标服务端转换器的派生产物；匹配坐标、编号、格式和覆盖保护。遇到已存在输出，选新目录或保留旧文件，不盲目重复构建。
- 结构验证、可走区语义、游戏落地/行走分别记状态。光照或局部 clearance 警告不能混同无导航输出，也不能写成“地图检测全零”。

## 5. 场景导出与地图登记各自闭环

- 优先调用当前地图的原生场景导出，避免无关全局批量遍历或碰撞重设。临时失效的源控自动 checkout/add 仅在该作用域隔离，结束恢复。
- 导出可能更新 Actor ID、刷怪列表等；回读结果并保存主图和变更子图。空 NPC 场景文件可以很小，按格式判断，不把它当地形。
- 中间 XML 用标准解析器核验。XML 产生不等于已汇入全局索引；区域、导航点和传送链接分别确认。
- 表扩展名不等于分隔符。检测实际编码、TAB/逗号、表头/用途/默认值行和等列数；有些旧读表器将数据中的空白行视作结束。避免文本工具双重换行转换。
- 通过项目原生登记入口以 ID 增量合并，保留表未列出的地图和缺失字段。用旧版少量条目的整表覆盖新版索引会破坏非目标记录。
- 回读客户端场景 ID、主包名、配置名及服务端编号；残留节点的图片名不是正式登记证明。显示名、客户端导出名和服务器配置名不能混同。
- 将同名索引副本、备份和旧地图放到包搜索范围之外；必要时唯一暂存名保存、归档后恢复发布文件名。保存查询超时先看重复包提示和磁盘证据，别重复写入。
- 全局刷新传送图可能清空重建数组。没有确认全部输入来源时不拿它完成单图登记；首轮基础登记和后续附加索引分开验收。

## 6. Cook 是运行转换，不是封包或伪改标志

源 UDK、Cook 后的 UDK 都可用同一扩展名。SeekFree 客户端需要运行数据，直接把 Content 源图封入发行目录可能通过初期加载，却在地形等延迟初始化时失败。

- 出现循环异常先看本次新转储。每帧捕获日志相同，不说明根因相同：编辑器类绑定失败与 BulkData 空 archive 是不同故障。
- 若堆栈指向地形 CollisionHeightData/BulkData，核对源数据存在、包状态和加载器生命周期。资源库的 lazy archive 在 SeekFree 完成后被 detach，不能靠补 PHX/NAV 修复。
- 使用目标兼容的原生 CookPackages 做真实转换。不能仅改 cooked/disallow-lazy 标志、删除有效地形碰撞、换扩展名或改客户端 EXE 掩盖问题。
- 普通 Cook 与 DLC Cook 选择取决于目标发布方式。用户指定普通地图时显式列入主图及流式子图，不擅加 DLC 或 AUTOCOOKMAPS/全库重构。一例普通 Cook 成功不证明任意新版 Cooked 资产都能安全重 Cook。
- 旧工具配置加载器可能自行拼接相对前缀；检查实际解析的 BasedOn。游戏根外的编辑器脚本可能触发 Cooker 路径断言，必要时复制匹配脚本到隔离会话内，不动原脚本。
- 搜索资源子目录，排除新版发布脚本所在根和重复同名源包。显式限定 Cook 列表，并核对日志实际处理内容；首次空输出的 full recook 提示不必然等于整个游戏全量 Cook。
- 某些旧 Cooker 固定输出活动 CookedPC。必须关闭使用该目录的编辑器、客户端及相关网关/索引进程，核实绝对路径后隔离输入和空输出；finally 归档产物并恢复原目录。现有脚本未证明可重用时，不照抄固定实验会话目录或覆盖已存在输出。
- 隔离前记录源文件 hash 和输入基线，结束检查源未变及目录恢复。不要为一次新增地图把新版已发布全库交给旧 Cooker 重做。

## 7. 发布清单按真实依赖生成

- 地图从成功 Cook 输出取，不从 Content 取；包括完整主图和实际引用的流式子图。同一目录里不要混入旧主图/新子图。
- 自定义 PHX/NAV/SCN、地图索引和配置分别从本轮已验证来源取；它们不由 Cook 自动代替。地图修改后核对是否需要重导，纯运行转换不自动要求重建导航。
- GuidCache 以目标客户端当前缓存为基线，验证只新增/更新目标包，没有删除或误改既有记录；不要用旧工程全局缓存覆盖新版缓存。
- 新依赖 UPK、TFC、shader 等按 Cooker 输出和客户端需求判断。一轮未产新 TFC 不等于将来永远无需 TFC；不要无依据发布整套编辑器脚本、持久 Cooker 数据或全局 shader 缓存。
- 各文件记录相对路径、字节数、SHA256 和来源会话，与实际封包输入逐项比较；后续使用不同客户端基线时重新合并缓存，不盲用历史补丁。
- 巨大重复日志取首尾有限片段并查新转储，不一次全文读取。对每次修复重新识别异常类型，不把重复字符串当旧故障未修复的证据。

## 8. 最小阶段验收与止损

先完成一个空图的进入/落地，再按用户目标验证行走、碰撞/边界、寻路、退出/重登、NPC、传送、小地图。完整制作流程要有这些验收项，不需要每次小修改都编译、重启或全量扫描。

记录五层结果：原生任务完成、文件结构、数据语义、实际部署一致性、游戏行为。用户确认能进入地图只通过入图 Gate，不自动证明其余玩法正确；把确认日期、反馈来源和未验收项一起保存。

超时先回读状态；路径/类/导航/Cook 问题分别处理。遇到连续失败，停止盲重试并缩小证据范围，不叠加关闭碰撞、重构全库或无关稳定性修补。
