# 资源发现与局部动效

适用于寻找可复用粒子、灯光等资源并放到现有模型局部。这里记录决策流程，不规定候选资产、对象编号、坐标、颜色或参数配方。

## 先查索引，再核对实际作用链

- 先读当前能力与 `ue3.search.index_status`，确认缓存对应当前资源版本、目录、覆盖范围及失败/跳过项。新旧资源不能混用索引；有缓存不等于覆盖全部包或刚保存的改动。
- 用 `ue3.search.query` 从效果语义、相关类别/包族逐步缩小范围，结合类过滤、精确名称及包范围分页查询。无结果先检查范围、匹配方式、路径格式和覆盖情况，不反复重扫整个资源库，也不直接断言资源不存在。
- 从候选对象查 `ue3.references.trace` 和 `ue3.package.properties` 的缓存结果，了解引用字段及可用锚点信息。区分“发现引用候选”与“目标对象已解析并可加载”；单跳出向引用不是完整双向调用关系，结构化属性缓存也可能尚未建立。
- 缓存缺失时，说明缺的是索引、属性还是实际资源。依当前授权决定是否询问用户后真实解析相关包，或通过 `ue3.search.index_refresh` 更新/重建缓存；不把一次未命中升级成自动全量扫描。用户已明确接受跳过的损坏包，不扩展成解密修复任务。
- 命中后只加载编辑所需的少量候选包，用编辑器实际对象树、组件引用与截图确认。离线导出名或关系不证明运行时模板可用；不用加载整组角色/坐骑数据来代替确认一个已定位的特效包。
- 搜索接口存在时直接复用；仅当现有接口确有缺口或批次编排有实际收益时写辅助脚本，不在脚本中另造一套全盘搜索逻辑。参数以当前 Schema 为准，不在 Skill 固化调用 JSON。

## 复用效果时检查行为，不只检查名称

- 看实际材质、位置分布、速度、生命周期、生成率、循环方式、LOD 和有效模块。外观相近的弹道、爆发或拖尾特效，不自动适合持续的局部光焰。
- 连续效果要核对相关发射器的循环与生成行为；不要仅凭系统名或一个循环字段判定整个系统会持续播放。用有效实时预览下的时间变化检查生命周期，而非只看一张静态截图。
- 需要改变行为时先建立独立变体，保留无关模块与依赖。若局部效果带着不合适的远距离喷射或运动光尾，应处理副本中的运动贡献，不单靠移动 Actor 或缩小整体效果掩盖。
- 缩放同时可能影响尺寸、位移与速度，且效果是否使用局部空间会改变表现。调尺寸后重新核对锚点、运动包络和相邻几何，不把 Actor scale 当作只有可见半径一个效果。
- 材质和 HDR/Bloom 会使本应饱和的亮点偏白。依据实际图片调节已确认的贡献，不为局部粒子擅自调整全局曝光；用户认可的亮度保留，位置校正不附带加亮。

## 局部放置与分层验证

- 几何位置与运动分布分开验证。优先锚点；没有锚点时用三视图、近景与用户标注核对局部形状，再确认深度、遮挡和粒子亮点实际落点。种类、朝向或镜像改变后不能沿用先前的解剖假设。
- 透明火焰并不能透过不透明外壳。没有可见粒子时检查发射点、腔体、深度与遮挡，再检查激活/预览状态，不直接持续放大或加亮。若只能做表面近似而非真正腔内效果，明确说明，不把外贴效果称作内部燃烧。
- 可见粒子、照亮模型的灯、模型材质自发光是不同层。呼吸灯不自动驱动发光贴图；火焰本身不保证会照亮周围。按用户目标分别处理必要贡献，不为完整感随意新增灯光。
- 呼吸/闪烁优先复用已有时间驱动控制；在不连续写入的情况下跨时间回读并观察。参数变化证明灯在变化，不能代替火焰可见、位置正确或游戏运行验证。
- 镜像对象的锚点位置需依据各自实际变换转换，方向性粒子还要检查运动方向和左右模板差异。每侧分别检查近景，再从使用视角检查整体比例；详细判断见 [模型放置经验](model-placement.md)。
- 用 G 模式清除辅助显示后查看实际渲染，观察完成恢复显示状态；具体判断见 [视觉归因经验](visual-diagnosis.md)。位置不符时优先接受用户标注作为目标约束，不以“已回读成功”拒绝视觉纠正。

## 交付与保存边界

一次编辑可按需遵循 `缓存发现 → 实际绑定/内部对象确认 → 独立变体 → 局部预览与校正 → 用户确认 → 授权保存`，不要求每个字段都重复截图、重载或全套测试。

新引用涉及新资产包与其所属关卡/流式子关卡时，保存清单必须同时覆盖资源和引用所在关卡；只保存地图可能留下未落盘依赖。未执行保存/重载/游戏验收的步骤明确标为未验证，不把预览、用户选择保存或文件存在等同于完整发布成功。
