# 贴图映射与 UV 重烘焙

在换肤、跨模型拼接图案或石块/分片表面出现拉伸、错位时读取。这里提供判断分支，不规定某个场景、资产名称、视口编号或分辨率。

## 先确认材质控制点

- 从实际 Actor、MeshComponent、网格及材质槽追踪到有效材质实例和纹理参数。可动模型不一定属于 StaticMeshActor；类过滤无结果时检查实际类，避免漏掉 InterpActor 等对象。
- 多材质模型只替换承载目标图案的槽。记录其他槽和对象变换，完成后回读；不要为了换一个局部图案改全部材质或共享基础模板。
- 材质实例的有效参数与基础图节点的默认贴图不同；核对参数覆盖和真实输入链。一个纹理也可能同时控制高光和 opacity mask，不能凭名称用普通灰图替换，意外消除孔隙或切口。
- Cooked/GPU 导出可能只是显示参考，缺少原始精度、透明度或源法线。工具返回异常尺寸、压缩或 mip 元数据时，不盲目继承；以可验证的图片尺寸、角色、sRGB 和实际渲染为依据，明确未知项。

## 整体 UV 范围不等于局部映射正确

一张图在左模型使用左半、右模型使用右半，只说明总体采样范围正确。各石块或分片仍可能拥有独立 UV 岛、不同缩放或偏移，导致眼睛、文字等连续结构在边界断开。

| 现象 | 优先核对 | 不能直接推断 |
|---|---|---|
| 每片都显示同一个图案 | 重叠/重复 UV、采样通道、材质平铺参数 | 调整整张图尺寸就能修复 |
| 图案大致完整，但接缝错位 | 每岛的 UV 与表面位置对应、局部拉伸 | 只是图片构图不好 |
| 换漫反射后仍有旧浮雕 | 有效法线、高光/遮罩、真实模型几何 | 漫反射替换失败 |
| 正面连续，侧视有断层 | 石块深度、倒角、遮挡与投射方向 | 全部 UV 都已修复 |

有必要时使用已支持的只读网格导出/检查后端，分析目标材质段的三角形、位置、UV、法线和切线。不要把外部只读检查说成 MCP 已具备网格写入能力；MCP 缺少某项接口不自动授权修改引擎源码。

- 检查当前使用的 UV 通道及其局部尺度、岛边界和重叠。备用通道可能是 lightmap 打包，不能未经验证就切换。
- 对近似平面图案，可比较表面位置与 UV 的拟合/邻边对应来定位偏移，但整体范围或平均误差不能单独证明每块都一致。
- 多模型拼接时先核对当前变换和坐标转换，组合到同一投射空间；移动、旋转或缩放变化后，旧烘焙关系可能失效。

## 保留模型时，按实际 UV 反向烘焙

当目标是让图案从指定方向连续、又需要保留石块和原模型时，可以把获批图案先投射到共同表面空间，再按每个原 UV 三角形重采样到独立贴图。贴图文件里各岛可能显得扭曲；正确标准是回到模型上是否连续，而不是图集是否仍像一张完整画。

采用前需确认用户允许此类确定性重采样。美术生成与 UV 烘焙是不同工作：后者使用现有获批图片，不应重新生成一张不同设计来掩盖映射问题。

- 投射范围、构图裁切和轴方向应来自真实几何及当前变换。不要把某次任务的固定坐标、上下边距或投射矩阵当通用配方。
- 检查 UV 重叠是否要求同一像素表达不同位置。可见正面无冲突不证明整个模型无重叠；背面、侧面和倒角需单独考虑。不同模型可用独立图集/材质隔离冲突，同一模型内无法兼容的重叠则需改变方案。
- 对有授权的模型副本，可考虑修改 UV；工具没有网格导入/编辑能力时明确说明。不能靠同一像素反复重画解决真正的冲突，也不未经授权改原网格。
- 给岛边缘适当扩边，减少双线性过滤和 mip 采样到空白背景；接缝或孔隙的透明度按原用途保留。边缘扩充不替代实际尺寸与远景渲染检查。
- 原有石缝、高低差和浮雕是几何，不会因重烘焙消失。平面投射主要保证指定方向的连续性，不保证所有视角一致；需要消除真实浮雕时属于额外模型修改。

## 法线不能只当普通彩色图片处理

- 漫反射修正后，旧法线仍可能留下旧图案。需要更新时，法线与漫反射使用一致投射，但还要处理切线空间、UV 方向/镜像及模型法线，不能假定复制同一张蓝紫图即可对齐所有岛。
- 核对 UE3 的法线约定、normal 导入角色和非 sRGB 设置；保留模型实际凹凸还是覆盖其表面法线，是不同目标，不擅自把原几何“抹平”。
- 图片模型生成的法线只是候选近似，不等于从高模或可信高度场烘焙的物理正确法线。降低其影响或重新烘焙应由实际视觉问题决定，不固定一套强度值。

## 导入失败、验证与保存

- 检查图片真实像素尺寸，不相信生成提示词中的尺寸要求。满足当前接口的二次幂、格式和预算；仅需适配尺寸时使用授权的确定性转换，保留原图，不反复调用图片模型碰尺寸。
- dry-run 接受输入不证明 TextureFactory 导入成功。apply 明确报错、事务取消也可能留下同名或不完整对象；先查询目标包、对象、源数据和当前绑定，不直接重放整批导入。
- 大尺寸失败、小尺寸成功，只是当前部署的观察，不能推广为 UE3 通用上限。缩小尺寸能满足当前目标时可用新的隔离目标验证，不为局部换肤无界调查或擅自编译引擎。
- 已有残留对象时使用新的版本名称，保持成功与失败资源可区分，不覆盖或保存无效测试包。没有安全删除接口时说明残留和“不保存”的范围，避免用户保存全部时混入。
- 新纹理与材质建独立包，只绑定授权实例/槽；验证实际引用、其他槽未变，再查看真实 MCP 截图。对照保留视角、显示模式和照明；用户指出接缝问题后，应补查内部 UV，不仅重复确认参数成功。
- 等保存状态完成并核对落盘文件，不能把 queued 当完成。资源包已保存、关卡绑定已保存、重载正常及游戏发布可用分别报告；本轮只验证预览就不要声称后两项通过。
