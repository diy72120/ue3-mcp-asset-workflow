# 地编资产库的观察与分类

适用于已经完成基础索引及模型图采集、准备逐图标注的资源库。这里记录证据与决策经验，不规定某张地图、资产名、固定相机或分类配方。工具参数与存储路径读当前工具参考。

## 远端 MCP 是唯一操作入口

- 整个观察分类流程只使用已连接的 MCP：读基础信息和分类树、领取目标、取图及回看、操作镜头/G、写回、检查完整度与保存交接。禁止客户端读 SQLite、本地缩略图、桌面截图或调用本机 CLI；不以 Shell/Python 脚本替代已提供的 MCP 工具。
- 图片直接阅读 MCP 返回的 Image 内容块，并用返回的编号、目标 ID 和 evidence_id 对应。路径字符串不是已经看过图片的证据；不要调用本地图片查看工具。回看历史证据也通过 MCP，而不是记住服务器文件名。
- 直接将标注记录作为 MCP 参数提交，不先创建本地 JSON、CSV 或脚本。dry-run 计划、验证反馈与交接由服务端 MCP 持有，下一位 AI 从工具读取，不依赖前一位 AI 的临时目录。
- 服务器内部解析包、生成图片、写缓存及保存数据库是工具实现，不是客户端越界。远端 AI 既不需要访问服务器磁盘，也不要求用户转发模型图。
- MCP 工具未接入、接口缺失或客户端无法接收 Image 时，明确报告具体缺口；不能悄悄退回本地文件操作后声称整套远程流程已通过。

## 先核对范围，再领取目标

- 基础库完成仅表示覆盖范围内的正常项已经采集、失败有记录，不表示语义分类或全部地图已完成。核对版本、源索引失败范围和是否仍有采集作业；不为标注重复建立全库。
- 以地图真实文件身份和当前已加载层为范围。单独打开子关卡可完成这一文件的观察，但不能称作整组场景已处理。
- 通过 Actor/组件的真实模型引用匹配库记录，再按模型及有效材质外观去重。摆放实例数、分类目标数和资源包数是不同计数。
- 未匹配项先区分真实游戏资源缺失、同名对象歧义、范围外依赖与编辑器辅助几何。引擎路径和辅助 Actor 类是调查线索，不是忽略所有引擎资源的依据；运行场景也可能合法使用共用引擎模型。
- 如果完成 Gate 未区分范围外的辅助模型，保留明确阻塞与交接，不把它们混入新版游戏资产、不伪造已匹配，也不为只读观察自动改编辑器源码。

## 判断阶梯与停止条件

基础信息足以支持某个字段时，不为该字段重复取证；但“大类已确定”不等于整张表单已检查。名称、目录、材质引用、尺寸相互一致，可支持宽泛用途分类；颜色、形态状态或风格需要图像时仍应取模型图。名称与几何矛盾时降级为候选，不能让名称覆盖观察；尺寸来自模型原生轴向，不等于摆放后的世界高度。

需要图片时，通过 MCP 领取少量带编号的拼图，并保留编号到稳定资产 ID 的映射。相似名字或相似图不能合并不同对象。先确定可见几何，再检查仍未确认的用途、风格、颜色及状态；补场景以解决具体字段疑问，不只为细分用途。不要为了让记录看起来完整而猜测，也不要以谨慎为由漏写清楚可见的绿色、宽叶、茂密等外观。

### 何时必须补关卡观察

独立模型图主要回答“模型长什么样”，当前地图上下文回答“它在这里怎样使用、和谁搭配”。前者清楚不能替代后者；判断阶梯的停止条件针对具体字段，不是找到一个大类后停止整条记录。

| 当前缺口 | 下一步观察 | 不能直接下的结论 |
|---|---|---|
| 拼图中目标太小、暗或遮挡，只能写“块状/不规则/表面起伏”等泛词 | 先经MCP取该目标独立预览；若仍影响选材，再定位真实实例看必要的局部/角度 | 不能声称已全面描述，也不凭名字补细节 |
| 不清楚是整体还是部件，或角色与名称矛盾 | 查看该目标在当前图中的真实装配/摆放关系 | 不把孤立形状猜成墙角、屋檐、门板等确定模块 |
| 需要填写scene_use或pairing | 核对地图身份、实例对应，查看覆盖该实例区域的有效宏观上下文；不足才补局部 | 独立模型图和一般常识不能证明本次用途或配套关系 |
| 材质缺失、变体无图、透明片误形，或颜色/状态受到预览质量限制 | 看准确目标的真实有效材质实例及所需上下文，保留受光/Shader限度 | 灰色几何不证明本色，基准图不证明变体，绿色斑块不自动证明健康或苔藓 |
| 模型图与关卡表现明显冲突 | 复核完整目标ID、有效材质、证据身份和快照，再观察准确实例 | 不沿用错位图片或把其他对象的外观归给当前目标 |

- 逐图任务应核对当前地图与加载范围，并查看能覆盖待处理实例区域的宏观证据；已有有效证据可回看复用，不要求重复截图。全景只用于建立区域/用途认识，目标不在画面里或无法辨认时，不能给它套用这张图的语义结论。
- 先列本批的具体疑问，再按区域共用宏观图；只对仍有疑问的准确Actor/组件定位补图。尺寸、颜色或形态已有充分证据时不重复观察，不为每个模型强制拍多套图，也不无限换镜头。
- “尚未取场景图”“只有模型图”说明流程尚未做完。在当前地图可观察且字段需要场景证据时，应先补观察；不能给整批复制这一理由后宣布完成。独立待处理队列没有真实实例、场景提示/连接受阻等情况，可以临时记录缺口并保存交接，但须区分未观察与已观察仍不明。
- 观察后仍受遮挡、看不到必要结构、无法确认真实配套或颜色受光干扰时，保留已知字段，给该字段记录已看证据、具体限制和下一入口。未看到配套不证明模型没有配套；找不到有效实例也不授权改关卡、删对象或假造证据。
- 形态标签需尽可能提取互补信息：总体轮廓与比例、组成与排列、边缘/局部特征等适用维度。“不规则块状、表面起伏”若只能区别大类而不能区分同类模型，继续检查当前图像是否还有可见的区别特征。确实看不清就按需补证；不设硬凑字数/标签数量，也不猜隐藏细节。
- 已知特征分别保存到description和对应检索字段，未知只限定未确认部分。绿色斑块或纹样不足以确认生物/材料身份时，可记录可见颜色、分布和“苔藓状覆盖”等外观线索，不将相似外观写成确定物理事实。
- 回读时分别检查字段审核、语义深度、观察覆盖及地图Gate。complete说明字段有值或未知理由，不证明形态可区分、场景已看或标签正确；map_finish返回结果也不能代替这些质量检查。临时证据缺口若已持久化，仍须在交接中列出，不把旧记录静默重写来制造完整度。

## 图片身份争议：先核对，再决定是否阻塞

- 默认 `images(contact_sheet=true)` 返回一张带编号的拼图，多个目标共用同一个 Image 内容块。这不是多资产缓存串图；拼图里的每一格才对应一个目标。批次、顺序、可用图片数量变化会改变整张拼图字节，即便各目标的原图没有改变。
- `evidence_id` 标识服务器原始证据，不是任意批次的拼图或HTTP压缩版本。每目标 `source_image_sha256` 是原图指纹，`delivered_images[].image_sha256` 是实际传输图片指纹。HTTP可返回缩小/JPEG压缩预览；转码、尺寸或质量变化会改变回传字节，不代表原始证据变化。核对mime_type、width/height、source/delivery指纹，不能把拼图或压缩图哈希与原PNG哈希比较后报告“同一证据换图”。
- 编号只在当前响应有效，不能沿用上次拼图的编号或记住第几个模型。逐次根据返回的完整目标 ID、object_path、evidence_id 和 Image 前的身份文字建立映射；短 ID 是显示提示，不替代完整身份。
- `image_content_index` 按 Image 块从0计数，`mcp_content_index` 按全部 content 块从0计数。身份 Text 块也占 content 位置，不能把两种索引混用。客户端展示层可能只显示图片，仍需结合结构化结果核对。
- 不同目标确实可能得到相同预览：模型几何相同、共享外观、材质变体没有独立图或几何预览缺少贴图，都可能造成视觉重复。字节相同不是独立故障判据，不要为此阻塞整图，也不能合并目标身份或把基准色套用到变体。
- 首次怀疑串图时，仅对争议的少量目标调用 `images(contact_sheet=false)`，再以对应 evidence_id 调用 `evidence_image` 回取。比较同一目标、同一证据、同一来源修订的独立预览及原图/回传指纹；同证据换编码后仅回传指纹不同不构成故障。不得依靠记忆中的图片、其他批次排列或模型名称判断故障。全程仅用 MCP，不写下载脚本或本地图片文件。
- 若独立预览回取稳定、源图指纹和身份标签一致，而且看清了真实模型，可继续本批分类，不要求维护者介入、不重复重建缓存。之前基于错位认图的草稿必须重新核对后提交，不能继续沿用。
- 若同一证据的独立原图指纹实际变化、身份映射矛盾，或服务端明确返回原图与锁定指纹不符，只暂停受影响的目标/步骤并报告两次请求参数、完整 ID、evidence_id、原图/传输指纹、representation、来源修订与错误原文。未复现就写“待核实”，不把猜测写成已确认服务端损坏。
- 不能看到 Image、无法读身份字段或真正存在错误时，不为了推进而强填标签；请求缺失能力。哈希证明传输稳定，不证明图像语义准确或预览等同完整 UE3 渲染。

## 分类键、分类树与目标能力

- 写入前读取当前 `categories` 与 `annotation_schema`；对本批目标查询 `annotation_capabilities`，由 `target_kind` 和字段能力确认基础模型或材质变体。模型名称后缀、共用材质或批次中某条报错不能证明整批都是变体。
- `category` 是传统分类键，如 `prop`、`building_part`，不是分类树 ID，也不是中文名称。可用键以当前 Schema 为准；`category_ids` 才接收已存在的分类树 ID，中文 `name`/`display_path` 只用于展示和理解。
- 支持 `category_ids` 的基础模型可填写树 ID 并省略 `category`，让工具推导传统根类别；同时填写两者时必须一致。材质变体按其能力使用传统 `category`，不套用基础模型的旧 display_name 或多分类写入能力；新版 asset_name 独立支持基础模型和变体，两者不能混淆。
- “字段不支持”的未知理由必须针对当前目标核实。一次显示名或多分类报错只说明对应目标/字段受限，不据此给整个批次复制相同理由；可编辑的基础模型仍应正常填写。
- 类别列表若出现以 `base:` 等 ID 形式命名的类别，或键与树 ID 混淆，暂停受影响的写入并报告维护者。不要新建同名伪类别、把 ID 当名称，或自行操作数据库修补；普通观察仍只走 MCP。

## 逐项写完整，而非只填大类

写回前读取当前Schema，逐项检查资产名称、分类、描述及九类标签：用途、风格、颜色、外观状态、形态特点、构件角色、场景用途、搭配线索、其他标签。所有可辨认信息尽量写全；取证不足的字段必须写明确未知理由，不能默默留空。新增字段不会自动回填旧记录、清空旧标签或重置已分类队列；没有用户授权不要回修历史数据。

- asset_name 填便于检索且描述清楚的中文语义名，建议8至24字、最多128字；名称应说明主体及最有辨识力的形态、材质或用途，不能只复制原始文件名。保留原生路径与原始名称，不改资源身份。描述覆盖形状/构成、材料线索、外观和可复用用途，不复述纯编号。
- 用途包含合理的主要用途及可兼容次要用途；风格可写自然写实、卡通、奇幻、通用古风等有证据的宽泛风格，不强行猜具体地区、朝代或作者流派。
- 颜色记录图片支持的主色、辅色或综合色调。漫反射近似可提供明显的贴图主色线索，应注明证据限度；“不是完整Shader”不等于所有颜色都必须空白。无材质几何图不能证明本色。是否允许据此写颜色/状态还须核对当前工具的质量规则：若明确拒绝，应按要求补场景证据或记录具体缺口，不绕过校验，也不泛化为所有目标/所有部署都禁止。未知字段理由与描述中的外观断言保持一致。
- 形态特点shape保存低矮丛生、叶片宽大、叶丛茂密、柱状收束、框架镂空等轮廓/结构信息；外观状态condition保存表面粗糙、可见断裂、磨损、污渍、局部完整性等。局部看起来完整不证明所有面无损；绿色也不证明植物生理健康。
- 构件角色part_role区分整体和零件，不能只重复“建筑构件”大类。通用用途use可以是有依据的可复用途径；scene_use/pairing只能填写当前地图实际使用和同场组合线索，必须有当前精确目标的场景证据。
- 其他标签补充模块化、面片植被、尺寸级别等未被专用字段涵盖的信息。不要堆重复同义词或无证据的季节、用途、颜色，以字数代替索引质量。
- 个别字段不明时保留已知字段，用 unknown_fields 保存该字段缺口和具体原因。只有无法确定整体用途等必要语义时才把整个目标标成 unknown；不能因风格不明而丢掉清楚的颜色和形状。
- 读取 MCP 表单约定，写入启用全字段检查；工具预览漏填项后补值或真实未知理由，再 apply，最后通过 MCP 回读完整度。完整度通过只证明没有未检查字段，不证明标签语义必然正确。

独立预览的常见限度：

- 透明植被可能显示为矩形或交叉方片；它们是贴图承载几何，不因此归类为墙、板或立方体。结合叶片图案、材质和实际场景判断，不能声称离线预览等同真实透明裁切。
- 几何预览的灰白色不代表模型本色，也不证明积雪。漫反射近似只能支持可见贴图线索，不证明完整 Shader、发光或透明表现。
- 零厚度的水面、交叉效果面或背景面不一定是坏模型。结合有效材质与实际实例区分，不能把所有薄片自动归为特效。
- 深色、棕色、缺树冠或少叶不足以证明烧焦、枯萎或死亡。缺少这些状态证据时不填相应标签，但仍填写可见的形态、疏密、表面特点；基础类别可确定而细分用途仍未知。
- 同一模型的有效材质不同，外观结论只写入对应变体，不覆盖全部实例。没有独立变体图时不能借基准图证明变体颜色。

## 全字段填写的硬性工作规范

“尽量全面”指尽可能提取已知且可复用的信息，不是凭空补词。每个目标独立完成所有受支持字段的检查，不能只填 category 和 description；颜色、外观状态尤其不能遗漏，也不能只把它们埋在描述里。

| 字段 | 必须检查和填写的内容 | 证据边界 |
|---|---|---|
| 资产名称 asset_name | 清楚的中文语义名，说明主体及有证据的区分特征；保留真实对象身份。 | 新版支持基准模型和材质变体；旧 display_name 的能力限制不适用于该字段。 |
| 分类 | 准确基础类别，可多选合适的已存在分类树节点。 | 不以名称近似、中文名称或树 ID 代替传统分类键。 |
| 描述 | 主体、轮廓/构成、可见材料线索、主辅色、纹样、外观特点及常见复用用途。 | 简洁完整，遵守当前字符限制；不杜撰不可见背面、材质物理性质或具体历史来源。 |
| 用途 use | 主要用途，以及确有支持的次要用途/搭配场景。 | 宽泛用途已经足够时不无限取景；单次摆放不是唯一用途。 |
| 风格 style | 由形体、纹样、配色支持的宽泛风格，如自然写实、古风装饰、工业构件、奇幻。 | 不强行判断朝代、地区、艺术流派；目录只是线索。 |
| 颜色 color | 直接可见的主色、辅色、饰边/局部颜色及综合色调，作为独立检索标签保存。 | 漫反射近似可支持明显贴图色，不支持完整Shader推断；场景受光不是模型本色。 |
| 外观状态 condition | 表面纹理、粗糙/斑驳、局部磨损/污渍/破损、可见保全程度等。 | 材质状态受图片质量限制；“未见明显断裂”不同于“所有面完好”。轮廓/构成另放shape。 |
| 形态特点 shape | 轮廓、比例、部件组成、连接/排列、开口/截面、边缘及局部几何细节，多个互补且可辨识的短标签。 | 无材质几何图可以支持可见形状；不能只写完整/破碎，不猜背面、隐蔽结构或把贴图图案认作孔洞。 |
| 构件角色 part_role | 完整房屋、单扇门板、直墙段、墙角、屋顶、屋檐、基座等可辨认角色。 | 与category大类分开；无法确认整体/零件时说明缺口，不凭名称强猜拼接角色。 |
| 场景用途 scene_use | 当前地图实际承担的边界围挡、入口装饰、路边遮挡、院落地面等用途。 | 必须有当前目标的有效scene_context和准确map_id；不把一次用法设为唯一用途。 |
| 搭配线索 pairing | 当前场景中观察到的相邻/配套角色，如墙段搭配墙角、门板搭配门框。 | 角色线索不是兼容性保证；需有效场景证据，精确成员与变换另用assembly。 |
| 其他标签 other | 面片植被、模块化、尺寸级别或未被以上字段涵盖的辅助检索信息。 | 避免重复堆同义词，不虚构碰撞、动画或游戏行为。 |

执行时逐字段核对，而不是填完大类就停止：

1. 基础信息支持用途但不支持颜色/状态时，继续通过 MCP 看独立模型图；缺少所需字段的观察不是“已完成”。模型图足够就停止追加场景观察，只有具体疑问才补真实实例上下文。
2. 对每个字段选择“有依据的具体值”或“已观察仍无法确认的具体原因”。支持字段不能省略、空字符串、只含空格、空数组后不说明；不能用“其他”“默认”“未知”标签机械填满。
3. 描述中出现清楚的红/金/蓝等配色时，对应颜色标签必须同步；草叶茂密、狭长等写shape，粗糙、斑驳、破损等写condition，明确构件身份写part_role。不得一边描述已知信息，一边说该字段无法判断。
4. 未知理由必须指出目标、证据限度和已观察步骤，例如“仅有无材质几何图，当前实例也受彩色光照，不能确认本色”。“没填”“没看”“节省token”“不重要”不是未知理由；不为整批复制同一理由。
5. 字段确实不受当前目标能力支持时，在 unknown_fields 写针对性的原因。个别字段未知不等于整个目标 unknown；保留已经确定的语义。unknown_fields 用于诚实记录缺口，不是跳过图片观察的捷径。
6. 提交通过MCP直接传tags.use/style/color/condition/shape/part_role/scene_use/pairing/other，启用require_complete_fields=true；当前契约检查12个字段，每项填值或具体unknown_fields原因。填scene_use或pairing须tier=scene_context、准确map_id及当前目标的有效场景证据；没有这些证据时写针对性的未知原因，不降级证据类型绕过检查。不得关闭检查或换写入口，不能靠旧dry-run计划提交不完整记录。
7. dry-run 检查所有 field_reviews，缺项先补再 apply。若工具拒绝某种证据质量，补真实场景或记录具体字段缺口，不借名称、描述或未知理由绕过规则。
8. apply 后用 annotation_check 核对本批 complete、missing_fields、unknown_fields、分类契约，再用 describe 回读实际字段。检查标签是否真的持久保存、是否与描述及图像相符；不能用“计划里有”“返回成功”代替持久结果。
9. 对所有出现未知理由的条目逐项复查：是否真的看过所需图片/上下文，是否已有足够信息却漏写。完整度 complete 只说明字段已处理，不证明内容全面正确；不可辨认内容保留未知，清楚可见内容必须写值。
10. 完成摘要明确：处理数量、仍未知的字段和原因、工具失败/未确认项。不能把未知原因覆盖的空标签说成全部字段都有语义数据。窗口仍空时通过 MCP 回读核对，而不是直接本地修库。

按新版字段分工：植物的丛生、细长叶、宽叶、疏松/茂密，以及构件的镂空、厚重/薄片、排列与构成写shape；表面斑驳、污渍、边缘损伤等写condition。绿色不证明健康，深色不证明烧焦；不能为了让状态非空而虚构这些结论。历史旧字段保留原样，不在观察新地图时顺手批量迁移。

## 形态描述要足以支持下一次选材

后续新标注以“另一位AI不看图片，也能大致想象轮廓、结构和摆放方式，能与同类资产区分”为目标。完整/破碎、正常/损坏只表达状态等级，不是完整的形态描述；名称、材质、颜色、用途也不能代替模型长什么样。

### 先观察这些维度

按目标实际可见的信息选择适用维度，不机械填满，不要求每个模型都有孔洞、装饰或磨损：

| 维度 | 应记录的可辨认信息 |
|---|---|
| 总体轮廓 | 圆形、方形、多边形、弧形、条状、柱状、团簇状、轮廓规则/不规则等；不要只写“大块”“构件”。 |
| 比例与体量 | 细长/粗短、高挑/低矮、扁平/厚实、宽窄变化、锥形收束、上宽下窄等。原生尺寸可辅助，但未核对摆放变换时不能当作世界高度。 |
| 构成与连接 | 单体或多件组合，底座/主体/顶部、框架/面板/支脚等组成，有哪些部分连接或彼此分离。 |
| 空间排列 | 直列/弧形/环形/放射状、疏密、重叠/错落、对称/非对称、平铺/堆叠、部件朝向关系等。 |
| 截面与内部结构 | 平板/实体/框架、凹槽/开口/孔洞/腔体、突出或内凹等；图片中的深色纹样不能直接当成真实几何孔洞。 |
| 边缘与表面 | 平直/圆滑/尖锐/参差的边缘，棱角、断口、木纹/石纹、条带、褶皱、接缝、粗糙/平滑等。 |
| 局部辨识特征 | 雕花、饰边、镂空纹样、铆钉、支撑、分叉、叶片形态、枝叶层次等；选择对同类区分最有用的特征。 |
| 损伤与外观状态 | 缺口/断裂/磨损的可见位置、范围、程度及其形状关系，而非只写“破损”。完整性只描述当前可见部分，不保证背面或内部。 |

尺寸、面数和材质引用是事实，不会自动生成这些语义；形态仍需与实际目标图片/上下文核对。只有单张图看不清且细节会影响分类或选材时，才补必要的局部或另一角度，不为凑字数给每个目标拍多套图。

详细不等于精确：模型原生XYZ包围盒尺寸、摆放后的世界尺寸、局部单件比例及透视图中的视觉估计分别注明。未测量不填精确倾角/比例；未数清不填确定部件数量，优先写细长、低矮、多个、略倾斜等有依据范围。尺寸关系与解析事实矛盾时先核对旋转/缩放/局部对象，不用透视观感覆盖事实。漫反射图中的亮斑不能证明金属反射，表面沟槽不能证明侵蚀形成过程；记录可见纹理/色斑，物理属性或成因不明时保留未知。

### 将观察分别落到表单

- description 写成清楚的整体描述：主体是什么、轮廓和比例如何、由哪些部分组成、如何排列、边缘/表面有什么特点，以及合理用途。对清楚可辨的模型写出多种互补特征，不能仅用“完整的建筑”“破碎的物体”结束；可在当前字符限制内用几句紧凑文字表达。
- shape保存有辨识度的轮廓、比例、构成及排列，如“细长弯曲”“分叉轮廓”“框架结构”“环形排列”；condition保存可见表面纹理和损坏细节。不统一套用“形体完整”，也不只把形状埋在description/other。
- part_role说明整体还是零件及具体模块职责；other保留模块化等补充属性。颜色、风格和用途仍放各自字段，不把所有信息堆进description而留空检索标签。
- asset_name 选取主体和最关键的区别特征；它是简明索引，不需要塞入完整形态段落。复杂结构的细节放description和标签。
- 具体数量仅在能数清时填写；看不清就写多件/簇状等准确范围。不要从名字或重复同类模板猜测数量、轮廓、隐藏结构、表面材质或损伤程度。
- 已知的轮廓/构成不应因为磨损、锈蚀或背面未知而全部省略。未知的是哪些细节就说明哪些细节，不把“未观察到背面”改写成整个外观无法判断。
- 如当前质量规则拒绝geometry_only/partial_materials的condition标签，先按需补当前场景证据；若仍无法确认，诚实记录该字段限制。已观察到的纯几何事实可保存在shape和description，但不伪装成材质状态、颜色或通过这些字段绕过condition校验。

### 实际用途与搭配的深度

- use回答“可用于什么”，scene_use回答“当前验证地图实际怎样用”。目录名称、独立图和一般常识可以支持有依据的通用用途，不能证明当前场景用途。逐图任务缺少所需场景图时先按上述触发条件补观察，仍无法确认才记录具体缺口；临时受阻可交接未观察事项，而不是编造摆放关系或把未观察说成完成。
- 利用已有宏观图和准确实例对应关系，优先提取真实的入口/边界/地面/遮挡职责及配套角色；宏观图能看清就不为每个目标额外截图。画外、遮挡或只有邻近但无配套证据时不填虚构关系，必要时才取局部图。
- pairing保存观察到的角色关系，不能声称“任意屋檐都兼容任意屋顶”。要复用准确房屋/院墙组合时，由用户或AI明确成员并用assembly保存引用和相对变换；文字标签不替代组合数据。
- 场景标签是有地图来源的使用实例，不是唯一用途。再遇其他用法时读取现有标签和修订历史，保留正确值并补充新证据；不要默默覆盖前一位AI的有效结论。
- 形态、构件职责和用途足以支持筛选，但不保证文字即可自动正确拼装。尺寸/原点来自解析事实；碰撞、精确朝向、拼接锚点和隐藏面未经核实就保持未知，不要求AI为了“深度”猜造这些事实。
- 检索优先使用当前Schema提供的字段过滤，例如filters.shape、part_role、scene_use、pairing；同字段多个精确标签为同时满足，跨字段通用标签可用required/excluded/preferred_tags。查无结果可能是未标注/未知或词汇不一致，不等于项目没有该模型。

写前及回读自查：这份记录是否除了损伤等级，还说明了外形、比例和结构关系？能否把它与相同类别但不同轮廓/组合方式的模型区分？描述里的可检索特征是否真的保存为相应标签？完整度complete仅检查字段处理情况，不保证形态足够详细；不能为了“详细”凭空补隐藏细节。

## 资产名称与原始资源名分离

- 先读当前 annotation_schema 和逐目标能力。asset_name 是AI填写的中文语义名；name、full_path、包文件和稳定ID仍是原生身份。旧 display_name 仅为可选兼容字段，不满足新版资产名称必填要求。
- 已有建议名称应正式写到 asset_name，不再仅放在 description、note 或 unknown_fields 中。禁止因为变体不支持旧 display_name 就声称“资产名称无法填写”；应检查当前 asset_name 能力。
- 优先采用“主体 + 明确的结构/材质/用途特征”，少量信息即可清楚区别同类模型；不把完整描述、所有标签或无证据的颜色/状态塞入名称。对只能宽泛识别的目标使用准确的宽泛名，不为了中文名猜具体对象。
- 基础模型与材质变体独立命名，不把某个焦黑、积雪或染色变体的名称推广到基准模型。模型浏览列表展示基准模型的资产名称/原始名称；只给变体命名不会自动改变基准模型的列表名称。需补基准名称时按 base_asset_id 单独核对语义及授权范围。
- 名称写回使用MCP的计划/应用及修订检查，回读 asset_name 和原生 name/full_path。补名字不能顺手重写已有颜色、状态或分类；现有 annotate 要求完整记录时，先读取原有值并保留，不能把未传字段当作可以清空。

## 场景补证不变成场景修复

- 宏观图复用当前有效镜头或合适的场景相机；局部观察必须绑定准确 Actor/组件与目标 ID。宏观图里的可见区域不自动证明所有已加载目标都可见。
- 按需开启 G 模式隐藏图标；观察前记录镜头及显示状态，结束恢复。隐藏图标不会解决真实遮挡、默认材质或未构建灯光。
- 包围盒自动取景可能看到背面、邻近物或穿入建筑。先检查截图是否真的支持目标用途，再决定补一个更有辨识力的角度；仍不明就停止，不无限取图。
- 受蓝光、红光照亮的石头不能按灯光颜色标注本色。画面偏暗、灰面或未构建提示属于当前观察限度，不授权修改材质、重建光照、保存或发布。
- 模型图清楚时，可停止为已确认的基础形态/外观字段追加取证；这不适用于scene_use/pairing，也不适用于仍有角色、材质变体或整体/零件疑问的字段。场景只能说明本次用途，不能把单次摆法升级为模型唯一用途。

## 回修与接手不依赖客户端临时文件

- map_batch默认过滤已classified目标；空队列不证明历史ID丢失。回看/回修已分类项时指定准确map_id与include_classified=true，再按游标分页。地图完成与否不替代这一查询参数。
- 如果工具提示当前编辑器地图不匹配，先检查未保存内容，再按明确map_id使用map_begin的计划/应用打开并核对目标图。这是更新该图的实例快照，不是重建全库索引，更不是重置历史分类；不要让用户手工重建ID清单。
- 目标身份、标注历史和已存证据通过describe/images/evidence_image读取；客户端/tmp、旧JSON或图片临时文件丢失，不等于服务器数据库资料丢失。下一位AI从服务端短交接恢复，不要求复制本地目录。
- 单个记录的材料质量/字段拒绝不能推广到整批。混合批次报错时查看具体目标与证据；错误未指出目标时，有限缩小到单项dry-run定位，再继续其他正常项。不复制统一未知理由或把基准模型误称为变体。
- 当前部署的diffuse_approximation可支持明显的漫反射主色和可见外观，但不保证完整Shader；geometry_only及partial_materials存在材料证据限制，stale需要刷新。远端报告“仅geometry_only受限”不能替代当前Schema/实际校验，也不能成为放宽其他质量限制的规则。
- “Context evidence belongs to a previous map snapshot”表示场景证据与当前已验证快照不一致，不等于资产被删除、不能命名或MCP永久不支持该目标。检查当前地图/真实实例，在当前有效快照中通过context取新证据，再生成新计划；仅换AI或客户端临时文件丢失本身不是过期判据。
- 已存旧标签不会因证据过期自动清空，但把旧scene_context记录重新提交时工具会复核证据。即使只补名称，也不能把旧场景结论改称metadata、去掉证据或伪造当前快照来绕过检查；保留原数据，按需重新观察，仍受阻就明确交接。
- 更新已有记录前通过MCP读取当前revision和各字段，保留无关正确值，不重放旧计划或旧分页游标。语义未知、证据限制、过期需重取和真实工具故障分别报告，不把这些状态都称为“服务端坏了”。
- 完成报告分别统计：字段审核complete、实际语义补齐、显式未知、未处理/受阻和地图Gate。按稳定ID核对总数与分地图计数；同一资产跨图复用时说明去重口径。各子项加总与总数矛盾时先核对，不把存在未完成目标的批次宣称全部完成。

## 写回与接手

- 标签是语义推断，解析事实保持原值。写全面且有证据的类别、描述及各表单字段；具体用途无法确认时用 unknown，并记录已看过什么、缺什么，避免下一位 AI 重做同一轮无效观察。
- 分类证据对应精确目标和当前版本；场景快照失效后重新核对，不能借别人的图片或旧 Actor 位置证明当前结论。
- 分页游标可能绑定修订版本。先读取当前批次再写回；标注改变版本后重新领取批次，不盲用写入前的游标。unknown 可能仍出现在待观察列表，结合尝试记录识别，不把再次出现当作未保存。
- 批量写回后读状态、修订或交接摘要，区分 classified、unknown、pending。工具返回 accepted 不等于已写入，更不等于游戏资源已保存。
- 写后通过 `describe` 与 `annotation_check` 核对实际 `category`、基础模型的 `catalog_categories` 中文名称、每项目标能力及 `category_contract_valid`（部署提供时）。契约无效或中文显示异常就停止完成申报；字段 complete、地图 Gate 放行都不能替代分类映射和语义核验。
- 完成报告从回读结果统计处理数、基础模型/变体数及类别分布，不按名字或记忆估算。区分主类别统计与分类树多选统计，后者可能重复计数；报告引用的未知理由应与实际记录一致。
- 分类完与地图 Gate 放行分开报告。保留目标处理数、未知项、未匹配范围、阻塞原因与下一入口；不把数据库 blocked 状态包装成完整 completed。
- 具体目标、截图和调用结果留在任务证据中；Skill 只保留改变后续判断的方法。

## 阻塞时反馈，不强行推进

- HTTP/SSE响应中断不证明截图或保存证据未完成。先用describe核对目标最近的scene_context、当前地图/实例和证据ID，再用evidence_image回取；不要重复重拍或把所有观察都记为失败。支持时可用context(include_image=false,max_dimension=512)先返回证据身份，随后取压缩预览。元数据不是已看到图片的证据，未成功读取Image仍不能写视觉结论；回取旧证据也须核对当前快照。
- 传输缩小后的图看不清细节时，先针对具体疑问取局部或按当前Schema提高所需尺寸，不要求传整张原PNG。恢复镜头/选择/显示状态仍需核对；服务器正常回传不证明其他AI客户端也能成功接收。反馈区分“服务器已捕获、客户端未收到”与真正原生捕获失败，不把一次公网成功写成历史断流根因已解决。
- 连接/认证失败、必需工具缺失、图片没有Image内容块、地图身份不符、编辑器崩溃/模态阻塞、写入结果未知或完成Gate拒绝，都属于流程问题。暂停受影响步骤，报告事实，不改源码、不转本地入口、不删对象来制造成功。
- 普通资产语义无法判断可按字段记录未知；工具故障不能用unknown标签掩盖。保留此前已验证写入，不因为后续故障宣称全图完成，也不盲目回滚其他人工作。
- 参数错误可查当前Schema做一次有依据的纠正；只读临时网络失败可确认连接后有限重试。写入超时先通过MCP回读目标revision、标签和历史，不重放结果未知的apply。不能核实时立即报告需要人工协助。
- 反馈包含：端点、当前地图/目标ID、步骤与工具名、安全的关键参数、请求ID（若有）、错误码/原文、已尝试的核对、已写入数量及剩余目标、是否恢复镜头/G、所需修复或用户协助。未知的结果明确写“未确认”，不猜测；不附令牌、认证头或整段图片Base64。
- 报告后等待用户处理，不无限重试、换图扫描或扩大任务。服务端问题留给工具维护者修复，观察AI不自行修补工具或游戏资源。
