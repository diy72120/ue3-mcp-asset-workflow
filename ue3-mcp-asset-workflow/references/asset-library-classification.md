# 地编资产库的观察与分类

适用于已经完成基础索引及模型图采集、准备逐图标注的资源库。这里记录证据与决策经验，不规定某张地图、资产名、固定相机或分类配方。工具参数与存储路径读当前工具参考。

## 远端 MCP 是唯一操作入口

- 整个观察分类流程只使用已连接的 MCP：读基础信息和分类树、领取目标、取图及回看、操作镜头/G、写回、检查完整度与保存交接。禁止客户端读 SQLite、本地缩略图、桌面截图或调用本机 CLI；不以 Shell/Python 脚本替代已提供的 MCP 工具。
- 图片直接阅读 MCP 返回的 Image 内容块，并用返回的编号、目标 ID 和 evidence_id 对应。路径字符串不是已经看过图片的证据；不要调用本地图片查看工具。回看历史证据也通过 MCP，而不是记住服务器文件名。
- 直接将标注记录作为 MCP 参数提交，不先创建本地 JSON、CSV 或脚本。dry-run 计划、验证反馈与交接由服务端 MCP 持有，下一位 AI 从工具读取，不依赖前一位 AI 的临时目录。
- 服务器内部解析包、生成图片、写缓存及保存数据库是工具实现，不是客户端越界。远端 AI 既不需要访问服务器磁盘，也不要求用户转发模型图。
- MCP 工具未接入、接口缺失或客户端无法接收 Image 时，明确报告具体缺口；不能悄悄退回本地文件操作后声称整套远程流程已通过。

## 先核对范围，再领取目标

- 基础库完成仅表示覆盖范围内的正常项已经采集、失败有记录，不表示语义分类或全部地图已完成。核对版本、源索引失败范围和是否仍有采集作业；不为标注重复建立全库。
- 以地图真实文件身份和当前已加载层为范围。单独打开子关卡可完成这一文件的观察，但不能称作整组场景已处理。
- 通过 Actor/组件的真实模型引用匹配库记录，再按模型及有效材质外观去重。摆放实例数、分类目标数和资源包数是不同计数。
- 未匹配项先区分真实游戏资源缺失、同名对象歧义、范围外依赖与编辑器辅助几何。引擎路径和辅助 Actor 类是调查线索，不是忽略所有引擎资源的依据；运行场景也可能合法使用共用引擎模型。
- 如果完成 Gate 未区分范围外的辅助模型，保留明确阻塞与交接，不把它们混入新版游戏资产、不伪造已匹配，也不为只读观察自动改编辑器源码。

## 判断阶梯与停止条件

基础信息足以支持某个字段时，不为该字段重复取证；但“大类已确定”不等于整张表单已检查。名称、目录、材质引用、尺寸相互一致，可支持宽泛用途分类；颜色、形态状态或风格需要图像时仍应取模型图。名称与几何矛盾时降级为候选，不能让名称覆盖观察；尺寸来自模型原生轴向，不等于摆放后的世界高度。

需要图片时，通过 MCP 领取少量带编号的拼图，并保留编号到稳定资产 ID 的映射。相似名字或相似图不能合并不同对象。先确定可见几何，再检查仍未确认的用途、风格、颜色及状态；补场景以解决具体字段疑问，不只为细分用途。不要为了让记录看起来完整而猜测，也不要以谨慎为由漏写清楚可见的绿色、宽叶、茂密等外观。

## 分类键、分类树与目标能力

- 写入前读取当前 `categories` 与 `annotation_schema`；对本批目标查询 `annotation_capabilities`，由 `target_kind` 和字段能力确认基础模型或材质变体。模型名称后缀、共用材质或批次中某条报错不能证明整批都是变体。
- `category` 是传统分类键，如 `prop`、`building_part`，不是分类树 ID，也不是中文名称。可用键以当前 Schema 为准；`category_ids` 才接收已存在的分类树 ID，中文 `name`/`display_path` 只用于展示和理解。
- 支持 `category_ids` 的基础模型可填写树 ID 并省略 `category`，让工具推导传统根类别；同时填写两者时必须一致。材质变体按其能力使用传统 `category`，不套用基础模型的显示名或多分类写入能力。
- “字段不支持”的未知理由必须针对当前目标核实。一次显示名或多分类报错只说明对应目标/字段受限，不据此给整个批次复制相同理由；可编辑的基础模型仍应正常填写。
- 类别列表若出现以 `base:` 等 ID 形式命名的类别，或键与树 ID 混淆，暂停受影响的写入并报告维护者。不要新建同名伪类别、把 ID 当名称，或自行操作数据库修补；普通观察仍只走 MCP。

## 逐项写完整，而非只填大类

写回前逐项检查：显示名称、分类、描述、用途、风格、颜色、外观状态、其他标签。所有可辨认信息尽量写全；取证不足的字段必须写明确未知理由，不能默默留空。

- 显示名称用便于检索的中文语义名，保留原生路径与原始名称，不改资源身份。描述覆盖形状/构成、材料线索、外观和可复用用途，不复述纯编号。
- 用途包含合理的主要用途及可兼容次要用途；风格可写自然写实、卡通、奇幻、通用古风等有证据的宽泛风格，不强行猜具体地区、朝代或作者流派。
- 颜色记录图片支持的主色、辅色或综合色调。漫反射近似可提供明显的贴图主色线索，应注明证据限度；“不是完整Shader”不等于所有颜色都必须空白。无材质几何图不能证明本色。是否允许据此写颜色/状态还须核对当前工具的质量规则：若明确拒绝，应按要求补场景证据或记录具体缺口，不绕过校验，也不泛化为所有目标/所有部署都禁止。未知字段理由与描述中的外观断言保持一致。
- 外观状态可写直接可见的低矮丛生、叶片宽大、叶丛茂密、形体完整、表面粗糙、明显断裂等，不必只在确认烧焦/枯萎时才填。局部看起来完整不证明所有面无损；绿色也不证明植物生理健康。
- 其他标签补充模块化、面片植被、几何结构、尺寸级别等有辨识力的信息。不要堆重复同义词或无证据的季节、用途、颜色，以字数代替索引质量。
- 个别字段不明时保留已知字段，用 unknown_fields 保存该字段缺口和具体原因。只有无法确定整体用途等必要语义时才把整个目标标成 unknown；不能因风格不明而丢掉清楚的颜色和形状。
- 读取 MCP 表单约定，写入启用全字段检查；工具预览漏填项后补值或真实未知理由，再 apply，最后通过 MCP 回读完整度。完整度通过只证明没有未检查字段，不证明标签语义必然正确。

独立预览的常见限度：

- 透明植被可能显示为矩形或交叉方片；它们是贴图承载几何，不因此归类为墙、板或立方体。结合叶片图案、材质和实际场景判断，不能声称离线预览等同真实透明裁切。
- 几何预览的灰白色不代表模型本色，也不证明积雪。漫反射近似只能支持可见贴图线索，不证明完整 Shader、发光或透明表现。
- 零厚度的水面、交叉效果面或背景面不一定是坏模型。结合有效材质与实际实例区分，不能把所有薄片自动归为特效。
- 深色、棕色、缺树冠或少叶不足以证明烧焦、枯萎或死亡。缺少状态证据时不填状态标签；基础类别可确定而细分用途仍未知。
- 同一模型的有效材质不同，外观结论只写入对应变体，不覆盖全部实例。没有独立变体图时不能借基准图证明变体颜色。

## 场景补证不变成场景修复

- 宏观图复用当前有效镜头或合适的场景相机；局部观察必须绑定准确 Actor/组件与目标 ID。宏观图里的可见区域不自动证明所有已加载目标都可见。
- 按需开启 G 模式隐藏图标；观察前记录镜头及显示状态，结束恢复。隐藏图标不会解决真实遮挡、默认材质或未构建灯光。
- 包围盒自动取景可能看到背面、邻近物或穿入建筑。先检查截图是否真的支持目标用途，再决定补一个更有辨识力的角度；仍不明就停止，不无限取图。
- 受蓝光、红光照亮的石头不能按灯光颜色标注本色。画面偏暗、灰面或未构建提示属于当前观察限度，不授权修改材质、重建光照、保存或发布。
- 模型图清楚时通常不需要场景证据；场景只能说明本次用途，不能把单次摆法升级为模型唯一用途。

## 写回与接手

- 标签是语义推断，解析事实保持原值。写全面且有证据的类别、描述及各表单字段；具体用途无法确认时用 unknown，并记录已看过什么、缺什么，避免下一位 AI 重做同一轮无效观察。
- 分类证据对应精确目标和当前版本；场景快照失效后重新核对，不能借别人的图片或旧 Actor 位置证明当前结论。
- 分页游标可能绑定修订版本。先读取当前批次再写回；标注改变版本后重新领取批次，不盲用写入前的游标。unknown 可能仍出现在待观察列表，结合尝试记录识别，不把再次出现当作未保存。
- 批量写回后读状态、修订或交接摘要，区分 classified、unknown、pending。工具返回 accepted 不等于已写入，更不等于游戏资源已保存。
- 写后通过 `describe` 与 `annotation_check` 核对实际 `category`、基础模型的 `catalog_categories` 中文名称、每项目标能力及 `category_contract_valid`（部署提供时）。契约无效或中文显示异常就停止完成申报；字段 complete、地图 Gate 放行都不能替代分类映射和语义核验。
- 完成报告从回读结果统计处理数、基础模型/变体数及类别分布，不按名字或记忆估算。区分主类别统计与分类树多选统计，后者可能重复计数；报告引用的未知理由应与实际记录一致。
- 分类完与地图 Gate 放行分开报告。保留目标处理数、未知项、未匹配范围、阻塞原因与下一入口；不把数据库 blocked 状态包装成完整 completed。
- 具体目标、截图和调用结果留在任务证据中；Skill 只保留改变后续判断的方法。

## 阻塞时反馈，不强行推进

- 连接/认证失败、必需工具缺失、图片没有Image内容块、地图身份不符、编辑器崩溃/模态阻塞、写入结果未知或完成Gate拒绝，都属于流程问题。暂停受影响步骤，报告事实，不改源码、不转本地入口、不删对象来制造成功。
- 普通资产语义无法判断可按字段记录未知；工具故障不能用unknown标签掩盖。保留此前已验证写入，不因为后续故障宣称全图完成，也不盲目回滚其他人工作。
- 参数错误可查当前Schema做一次有依据的纠正；只读临时网络失败可确认连接后有限重试。写入超时先通过MCP回读目标revision、标签和历史，不重放结果未知的apply。不能核实时立即报告需要人工协助。
- 反馈包含：端点、当前地图/目标ID、步骤与工具名、安全的关键参数、请求ID（若有）、错误码/原文、已尝试的核对、已写入数量及剩余目标、是否恢复镜头/G、所需修复或用户协助。未知的结果明确写“未确认”，不猜测；不附令牌、认证头或整段图片Base64。
- 报告后等待用户处理，不无限重试、换图扫描或扩大任务。服务端问题留给工具维护者修复，观察AI不自行修补工具或游戏资源。
